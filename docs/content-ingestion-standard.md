# 内容采集与入库标准

## 目标

这份文档定义 `zoed.signal` 的内容边界、筛选规则、结构化字段和前台呈现层级。

它是后续信息爬取、人工筛选、AI 整理、数据入库和简报生产的统一标准。

当前产品的核心用户先定义为：

- 以商科学生为主的大学生
- 同时覆盖其他专业、但希望理解最新商业科技新闻的同学
- 主要需求集中在求职、读研、面试和个人思维成长

因此，`zoed.signal` 不是泛 AI 新闻站，也不是纯技术资讯流，而是一个面向大学生的高价值商业科技信号筛选器。

## 核心原则

1. 只收对用户有真实决策价值的信息，而不是流量型热点。
2. 只收有明确来源、可追溯的信息，不收无法定位原始出处的二次传播。
3. 只收能够被解释成商业、职业或学习价值的信息，不收纯情绪内容。
4. 事实字段必须基于真实来源，AI 只负责整理、归类和解释。
5. 产品最终呈现给用户的不是“原文搬运”，而是“经过判断和转译的有效信息”。

## 用户价值判断

一条内容进入系统前，至少要能服务以下目标中的一项：

1. 帮用户理解 AI 和商业科技行业正在发生什么。
2. 帮用户判断哪些能力、岗位、公司和方向值得关注。
3. 帮用户积累面试、商赛、申请、写作可用的案例。
4. 帮用户建立更好的商业判断力和科技敏感度。

如果一条内容无法支撑以上任何一项，就不应入库。

## 内容主题范围

当前阶段建议固定为以下 8 个主题：

1. `AI Agent`
2. `企业应用`
3. `产品发布`
4. `商业化`
5. `融资并购`
6. `岗位变化`
7. `工具趋势`
8. `案例落地`

补充解释：

- `AI Agent`：多代理、自动化流程、垂类 agent、agent 基础设施
- `企业应用`：办公、销售、客服、投研、教育、医疗、咨询、创作等场景
- `产品发布`：模型、功能、平台、集成能力、生态能力上线
- `商业化`：定价、订阅、企业版、渠道合作、收入模式变化
- `融资并购`：融资、收购、战略投资、业务整合
- `岗位变化`：岗位新增、岗位取消、技能要求变化、组织结构调整
- `工具趋势`：工作流工具、协作工具、效率工具、开发工具变化
- `案例落地`：企业真实部署、使用反馈、ROI、失败教训、adoption 信号

## 纳入标准

一条内容只有满足以下大部分要求时，才建议进入正式库：

1. 与 AI 商业、职业发展、学习成长至少一项直接相关。
2. 有明确来源名和可访问来源链接。
3. 能够识别事件主体、事件动作和发生时间。
4. 不是单纯情绪表达、观点抒发或标题党传播。
5. 不是简单重复已有内容，至少在事实或判断上有新增价值。
6. 能清楚回答“为什么重要”。
7. 能解释它对大学生，尤其是商科学生的意义。
8. 能转化成简报价值、案例价值或求职表达价值。

## 剔除标准

以下内容原则上不入库：

1. 没有原始出处或来源不明的内容。
2. 只有社交媒体热度，没有可靠事实支撑的内容。
3. 纯技术细节更新，且无法解释商业或职业意义的内容。
4. 与大学生求职、读研、面试、成长关系很弱的泛娱乐 AI 内容。
5. 单纯“某模型很强”“某产品很火”但没有具体事实和影响分析的内容。
6. 与库内已有记录高度重复、只改写标题或措辞的内容。
7. 时效性已明显失效，且不具备复盘价值的内容。
8. 纯融资快讯，除了金额外无法说明业务、市场或岗位含义的内容。

## 内容优先级

### P0：优先采集

- 大模型公司和平台型公司的产品发布
- AI agent 和 workflow 方向的重要变化
- 企业真实应用案例
- 招聘岗位、技能要求、组织变化
- 定价、企业版、合作生态等商业化动作

### P1：次优先采集

- 融资并购
- 机构行业报告
- 创业公司增长动作
- 重点行业的场景落地案例

### P2：谨慎采集

- 论文摘要
- 泛媒体评论
- 社交平台热点讨论

P2 内容只有在能够明确转译成用户价值时才入库。

## 字段填写标准

### `whatHappened`

要求：

- 只描述事实，不混入观点
- 回答谁做了什么
- 尽量带上时间、对象或动作结果

### `coreSummary`

要求：

- 1 到 2 句话
- 适合首页或列表快速浏览
- 不是重复标题，而是提炼真正重点

### `whyImportant`

要求：

- 解释行业、公司、竞争、岗位或用户行为层面的变化
- 不能只写“很重要”“影响很大”

### `businessInterpretation`

要求：

- 明确指出商业模式、竞争格局、产品策略或组织能力层面的含义
- 这是本产品区别于普通资讯流的核心字段之一

### `relevanceToBusinessStudents`

要求：

- 直接说明它与商科学生的关系
- 可涉及咨询、市场、产品、战略、投融资、商业分析、运营等方向

### `interviewOrCaseUse`

要求：

- 明确用户可以怎么把这条内容用到面试、商赛、申请文书、课堂讨论或写作中

### `nextAction`

要求：

- 给出可执行动作
- 例如继续追踪哪家公司、补哪类知识、如何表达成个人观点

## 用户看到的信息层级

前台统一建议使用以下 5 层结构：

1. `原始事件`
2. `核心摘要`
3. `商业解读`
4. `对用户的价值`
5. `下一步建议`

对应关系建议如下：

- 原始事件：`whatHappened`
- 核心摘要：`coreSummary`
- 商业解读：`businessInterpretation` + `whyImportant`
- 对用户的价值：`relevanceToBusinessStudents` + `interviewOrCaseUse`
- 下一步建议：`nextAction`

这样做的目标是让用户看到的不是“新闻原文”，而是“被翻译成成长价值的商业科技信息”。

## 面向当前用户群的内容判断偏好

考虑到当前用户以大学生为主，系统在采集和筛选时应优先偏向以下类型的信息：

1. 能帮助理解未来岗位和技能变化的信息。
2. 能帮助判断值得关注的公司、行业和方向的信息。
3. 能作为面试或申请中案例素材的信息。
4. 能帮助建立商业分析框架的信息。
5. 能兼顾商科用户，同时让非商科同学也能读懂并获得价值的信息。

相应地，以下内容即使热度高，也不应优先：

1. 纯模型跑分
2. 纯社区梗和情绪讨论
3. 与职业和商业判断关系弱的技术八卦
4. 没有可复用洞察的短周期噪音

## 与后续爬取和入库的协作边界

这份文档只定义内容标准，不定义实现细节。

当前明确不处理：

1. 不写爬虫代码
2. 不接 API
3. 不改数据库结构
4. 不改 UI 细节
5. 不定义调度和自动化执行方案

但后续所有抓取、去重、AI 整理、审核和入库流程，都应以这份标准为准。

## 当前结论

在当前阶段，`zoed.signal` 的内容系统应坚持以下结论：

1. 收的是高价值商业科技信号，不是泛 AI 热点。
2. 用户价值优先级高于信息数量优先级。
3. 商科学生可用性是第一判断标准，兼顾其他专业大学生可理解性。
4. 事实必须来自真实来源，价值来自后续整理与解释。
5. 后续信息爬取应先服务这套标准，而不是反过来让抓取能力决定产品内容边界。
