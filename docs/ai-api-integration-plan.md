# zoed-signal API 接入方案（第一版）

## 目标

在不打乱当前前端和内容结构的前提下，把信息采集、处理、筛选和入库逐步自动化。

当前阶段不追求“一键全自动发布”，而是先做一条可追踪、可回看、可人工兜底的半自动内容流水线。

## 适合现在接入的范围

第一版 API 只负责内容加工层，不直接负责最终发布决策。

推荐先让模型做这些事：

1. 原始内容分类
2. 标签生成
3. 中文摘要
4. `whyImportant` 中文化改写
5. `relevanceToBusinessStudents` 中文化改写
6. `interviewOrCaseUse` 中文化改写
7. 是否值得进入精选池的初步判断

## 暂时不要自动化的范围

这些能力先不要在第一版直接全自动上线：

1. 无人工确认的自动发布
2. 完整用户偏好驱动的个性化简报
3. 自动决定首页展示优先级
4. 多来源融合后的复杂事实裁决
5. 高风险舆情或政策内容的自动结论输出

## 建议的第一版流程

### 第 1 步：抓取原始内容

来源可以先继续从 AI HOT 和你当前人工确认过的来源开始。

写入：

- `source_import_runs`
- `source_items_raw`

记录：

- `fetched`
- `imported`
- `skipped`
- `failed`

### 第 2 步：调模型做结构化处理

输入：

- 原始标题
- 原始摘要/正文片段
- 来源
- 发布时间

输出固定 JSON。

建议字段：

```json
{
  "title_zh": "中文标题",
  "summary_zh": "一句话摘要",
  "category": "AI 产品更新",
  "importance": "必看",
  "tags": ["企业软件", "OpenAI", "商业化"],
  "what_happened": "发生了什么",
  "why_important": "为什么值得关注",
  "relevance_to_business_students": "对商科学生的意义",
  "interview_or_case_use": "可用于面试/案例/选题的角度",
  "curation_stage": "selected",
  "confidence": 0.86
}
```

### 第 3 步：服务端校验 JSON

校验项：

1. 必填字段是否齐全
2. 标题和摘要是否为空
3. 标签数量是否在允许范围
4. 分类和重要程度是否落在白名单枚举里
5. 是否与已有新闻高度重复

不合格：

- 标记为 `failed`
- 把失败原因记到导入运行结果里

### 第 4 步：写入业务表

通过校验后再写入：

- `news_items`
- 需要时再聚合到 `briefs`

### 第 5 步：后台人工确认

第一版建议保留人工兜底：

1. 管理员可看导入结果
2. 可看每条内容的原始输入和模型输出
3. 可决定是否发布/隐藏

## 技术接入建议

## 模型调用位置

优先放在服务端：

- Next.js Route Handler
- 后台导入 API
- 未来的定时任务入口

不要在浏览器端直接调模型 API。

## 输出方式

第一版必须要求模型输出结构化 JSON，不要返回自由散文。

推荐要求：

1. 固定 schema
2. 固定枚举值
3. 中文输出
4. 摘要长度限制

## 错误兜底

每次模型调用都要记录：

1. 请求时间
2. 来源条目 ID
3. 调用是否成功
4. 解析是否成功
5. 入库是否成功
6. 跳过原因

## 推荐开发顺序

### 阶段 A：单条测试

先做一个后台按钮：

- 选 1 条 `source_items_raw`
- 调模型
- 返回结构化结果
- 不写正式表，只显示预览

### 阶段 B：可入库预览

把模型结果显示在后台，允许你：

1. 预览
2. 确认
3. 手动写入 `news_items`

### 阶段 C：批量半自动

支持一次导入多条：

1. 批量抓取
2. 批量模型处理
3. 批量校验
4. 后台人工确认
5. 批量发布

### 阶段 D：轻自动化定时任务

等前三步稳定后，再接：

1. 定时抓取
2. 定时处理
3. 后台待审核队列

## 进入“可正式接 API”的判断标准

满足下面这些条件后，就适合真正开工：

1. 首页和简报页字段结构基本稳定
2. 收藏夹和个人页不再频繁改字段
3. 前台中文化基本完成
4. 导入留痕已经可用
5. 后台能看懂每次导入结果

## 当前建议结论

下一阶段最适合做的是：

1. 先做“单条内容 -> 模型结构化输出”的后台测试入口
2. 再做“批量导入 -> 模型处理 -> 后台确认”
3. 最后才做“定时自动化”
